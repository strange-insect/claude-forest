# ants design notes

この文書は ants の設計思想と設計理由をまとめる。
使い方の説明は README.md を参照する。

## 目的

ants は、Claude Code の日常作業で繰り返し発生する定型的な操作を agent と skill として集約した基本プラグインである。

主な用途は次のとおり。

- 別セッションの AI（Codex / Opus）に質問・レビューを依頼する
- GitHub PR を作成する、PR 情報を取得する
- セッション会話を Markdown にエクスポートする
- PlantUML と Kroki URL を相互変換する
- 新しいカスタムスキルの雛形を生成する

ants 自体は特定のワークフローを強制しない。各 agent / skill は独立して使え、他プラグイン（例: silverfish）からの依存先としても利用される。

## 基本セットとしての位置付け

ants は「他のプラグインからも参照される共通機能の最小集合」として設計する。

そのため次の方針を取る。

- 他プラグインに依存しない（ants は依存される側）
- agent / skill 単位で疎結合に保ち、1 つの不具合が他に波及しないようにする
- フックは最小限にとどめ、ユーザーセッションへの副作用を抑える

現在 ants が提供するフックは `SessionStart` で `CLAUDE_SESSION_ID` を環境変数化する 1 件のみ。これは複数の agent（`export-session` など）が現在のセッション ID を必要とするための基盤である。

## agent と skill の使い分け

ants は agent（subagent）と skill（スラッシュコマンド）の両方を提供する。使い分けの基準は次のとおり。

- **agent**：独立コンテキストで実行したい処理。長時間処理・大量出力を伴うもの、または親セッションのコンテキスト履歴を引き継ぐ必要がないもの。Agent ツール経由で起動する
- **skill**：本セッションのインライン処理として実行したい処理。ユーザーが明示的にスラッシュコマンドで呼ぶことを前提とした対話的・記述的な操作

agent は親セッションのメッセージ履歴を引き継がないため、起動コストが軽く、独立した実行に向く。skill は本セッションの会話と密に絡むため、ヒアリングや既存ファイルへの編集など対話的な作業に向く。

## 別セッション AI agent

`codex-ask` / `codex-review` / `opus-ask` / `opus-review` は、いずれも subagent として独立コンテキストで動作する。

これらを agent にしている理由は次のとおり。

- 大きな調査・レビュー結果が本セッションのコンテキストを圧迫しないようにする
- 失敗・タイムアウトしてもユーザーとの本来の対話に影響を与えない
- セッション ID を返すことで、後続ターンでの継続会話・再質問を可能にする
- 親セッションのメッセージ履歴を引き継ぐ必要がないため、subagent の独立コンテキストが適している

ask 系 agent の結果はファイル（ログ）として返却し、本セッションには「ログファイルのパス」だけを渡す。これにより、利用者は必要な部分だけを Read して取り込める。

## 1問1答とセッション継続

`*-ask` 系 agent は、1 回の呼び出しで 1 問 1 答を行う前提で設計する。

複数ターンの議論が必要な場合は、前回の応答に含まれる `session_id` をユーザーまたは親セッションの LLM が明示的に指定して呼び出す。`session_id` を ants 側で勝手に補完しないのは、別話題の会話履歴を意図せず引きずるのを防ぐためである。

## レビュー専用 agent

`codex-review` / `opus-review` は、コードレビュー専用の agent として `*-ask` とは分離している。

分離する理由は次のとおり。

- レビューは「観点」「対象範囲」「ベースブランチ」など固有のパラメータを持つ
- レビュー結果は読みやすい構造化された出力にしたい
- 「コードを修正しない」という制約を明示的に持たせたい

レビュー系 agent は原則としてコードを修正しない。修正は、レビュー結果を読んだ本セッション側の LLM が、ユーザーの指示を受けてから行う。

## GitHub PR

`create-pr`（skill）と `get-pr-info`（agent）は `gh` CLI に薄くラップする形で実装する。

`create-pr` は本セッションでの対話的な PR 本文生成が伴うため skill としている。テンプレートはリポジトリ側のものを優先するが、引数で明示指定もできる。

`get-pr-info` は出力が長くなるため subagent として実装し、`/tmp/pull-requests/` 配下にファイルとして保存して本セッションにはパスを返す。

## エクスポート系 agent

`export-session` は、セッションの会話履歴を Markdown として書き出す。

これは作業記録の永続化を ants 側で担うためではなく、利用者が任意のタイミングで自分用の記録を作るための補助である。継続的なタスク記録は silverfish のような別プラグインの責務とする。

## PlantUML agent

`plant-uml` は Kroki サーバーを利用して、PlantUML ソースコードと画像 URL を相互変換する。Markdown 中のコードブロックと画像 URL の双方向変換にも対応する。

外部の Kroki サーバーにソースを送信する点に注意。機微な情報を含む図表に使う場合は、自前の Kroki サーバーを参照するよう設定する。

## メタ skill

`create-skill` は、新しいカスタムスキルの雛形（SKILL.md）を対話的に生成するための skill である。対話的なヒアリングとファイル生成を伴うため skill として実装している。

ants が「基本セット」として配布する以上、利用者がプロジェクト固有の skill を追加するシーンが多いと想定し、その立ち上げコストを下げる目的で含めている。
