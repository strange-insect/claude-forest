# ants design notes

この文書は ants の設計思想と設計理由をまとめる。
使い方の説明は README.md を参照する。

## 目的

ants は、Claude Code の日常作業で繰り返し発生する定型的な操作をスキルとして集約した基本プラグインである。

主な用途は次のとおり。

- 別セッションの AI（Codex / Opus）に質問・レビューを依頼する
- GitHub PR を作成する、PR 情報を取得する
- セッション会話を Markdown にエクスポートする
- PlantUML と Kroki URL を相互変換する
- 新しいカスタムスキルの雛形を生成する

ants 自体は特定のワークフローを強制しない。各スキルは独立して使え、他プラグイン（例: silverfish）からの依存先としても利用される。

## 基本セットとしての位置付け

ants は「他のプラグインからも参照される共通機能の最小集合」として設計する。

そのため次の方針を取る。

- 他プラグインに依存しない（ants は依存される側）
- スキル単位で疎結合に保ち、1 スキルの不具合が他に波及しないようにする
- フックは最小限にとどめ、ユーザーセッションへの副作用を抑える

現在 ants が提供するフックは `SessionStart` で `CLAUDE_SESSION_ID` を環境変数化する 1 件のみ。これは複数のスキル（`export-session` など）が現在のセッション ID を必要とするための基盤である。

## 別セッション AI スキル（fork コンテキスト）

`codex-ask` / `codex-review` / `opus-ask` / `opus-review` は、いずれも `context: fork` で動作する。

fork セッションを使う理由は次のとおり。

- 大きな調査・レビュー結果が本セッションのコンテキストを圧迫しないようにする
- 失敗・タイムアウトしてもユーザーとの本来の対話に影響を与えない
- セッション ID を返すことで、後続ターンでの継続会話・再質問を可能にする

ask 系スキルの結果はファイル（ログ）として返却し、本セッションには「ログファイルのパス」だけを渡す。これにより、利用者は必要な部分だけを Read して取り込める。

## 1問1答とセッション継続

`*-ask` 系スキルは、1 回の呼び出しで 1 問 1 答を行う前提で設計する。

複数ターンの議論が必要な場合は、前回の応答に含まれる `session_id` をユーザーまたはエージェントが明示的に指定して呼び出す。`session_id` を ants 側で勝手に補完しないのは、別話題の会話履歴を意図せず引きずるのを防ぐためである。

## レビュー専用スキル

`codex-review` / `opus-review` は、コードレビュー専用のスキルとして `*-ask` とは分離している。

分離する理由は次のとおり。

- レビューは「観点」「対象範囲」「ベースブランチ」など固有のパラメータを持つ
- レビュー結果は読みやすい構造化された出力にしたい
- 「コードを修正しない」という制約を明示的に持たせたい

レビュー系スキルは原則としてコードを修正しない。修正は、レビュー結果を読んだ本セッション側のエージェントが、ユーザーの指示を受けてから行う。

## GitHub PR スキル

`create-pr` / `get-pr-info` は `gh` CLI に薄くラップする形で実装する。

PR 作成時のテンプレートはリポジトリ側のものを優先するが、引数で明示指定もできる。PR 情報の取得は本セッションを汚さないよう、`/tmp/pull-requests/` 配下にファイルとして保存し、本セッションにはパスを返す。

## エクスポート系スキル

`export-session` は、セッションの会話履歴を Markdown として書き出す。

これは作業記録の永続化を ants 側で担うためではなく、利用者が任意のタイミングで自分用の記録を作るための補助である。継続的なタスク記録は silverfish のような別プラグインの責務とする。

## PlantUML スキル

`plant-uml` は Kroki サーバーを利用して、PlantUML ソースコードと画像 URL を相互変換する。Markdown 中のコードブロックと画像 URL の双方向変換にも対応する。

外部の Kroki サーバーにソースを送信する点に注意。機微な情報を含む図表に使う場合は、自前の Kroki サーバーを参照するよう設定する。

## メタスキル

`create-skill` は、新しいカスタムスキルの雛形（SKILL.md）を対話的に生成するためのスキルである。

ants が「基本セット」として配布する以上、利用者がプロジェクト固有のスキルを追加するシーンが多いと想定し、その立ち上げコストを下げる目的で含めている。
