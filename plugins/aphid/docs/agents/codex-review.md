# codex-review

OpenAI Codex CLI にコードレビューを依頼し、結果を Markdown ログファイルに保存する。`session_id` を使って指摘対応の追加レビューを同一スレッドで継続できる。

## 基本情報

| 項目 | 値 |
|---|---|
| agent 名 | `codex-review` |
| 実装 | `agents/codex-review.py` |
| 使用モデル | `sonnet` |
| 実行コンテキスト | subagent（独立コンテキスト） |

## トリガーフレーズ

- 「codexでレビュー」
- 「codexレビュー」
- 「codex-review」

※ agent 名を指定せず単に「レビューして」と言った場合は使用しない。

## 呼び出し形式

```
[session_id=<SESSION_ID>] [reinject_guideline=<true|false>] [model=<MODEL>] [effort=<EFFORT>] review_instruction=<レビュー指示>
```

### 引数

| 引数 | 必須 | 説明 |
|---|---|---|
| `review_instruction=<レビュー指示>` | 必須 | レビュー指示。原文のまま渡す |
| `session_id=<SESSION_ID>` | 省略可 | 指摘対応後に継続レビューする場合に前回の session_id を指定する |
| `model=<MODEL>` | 省略可 | 使用するモデル。**ユーザーが明示的に指定した場合のみ渡す** |
| `effort=<EFFORT>` | 省略可 | reasoning effort。**ユーザーが明示的に指定した場合のみ渡す** |
| `reinject_guideline=<true\|false>` | 省略可 | 役割定義・出力ルール・標準レビュー観点などの固定プロンプトを review_instruction の先頭に付加するかどうか。初回レビュー時はこの値に関わらず必ず付加される。継続レビュー時は `true` を指定した場合のみ付加される。`codex-ask` からの継続セッションで初回プロンプトを Codex に与えていない場合に指定する |

`review_instruction` の最もシンプルな例：「未コミットの変更をレビューしてください」。必要に応じて背景情報・対象範囲・比較元ブランチ名・レビュー観点を追加する。

## 親セッションへの応答

ログファイルのパスと、親セッションがユーザーに結果を提示するためのテンプレートを返す。

```
レビューログ: <絶対パス>

レビューログを読んで以下のテンプレートに従いユーザに結果を応答してください。
ユーザから明示的な指示がない限り指摘対応や修正を開始しないでください。

（応答テンプレート）
```

※ 親セッションはこのテンプレートに従ってユーザーに結果を提示する。

### 親セッションの応答テンプレート構成

親セッションがユーザーに返す応答の構成：

| セクション | 内容 |
|---|---|
| レビューログ / セッション ID | ログファイルパスと session_id |
| レビュー結果 | Codex の回答原文（全文） |
| 誤検知と思われる指摘 | 文脈不足・事実誤認・周辺確認不足による誤検知の分類 |
| 必須対応の指摘 | typo・バグ・検討の余地がない明確な改善点 |
| 要検討の指摘 | トレードオフがある・意思決定が必要な指摘 |
| 推奨対応 | 要検討の指摘に対する推奨対応 |
| 所感 | レビュー結果に対する所感 |

## レビュー観点

新規セッション（`session_id` なし）の場合、標準的なレビュー観点を記載した固定の指示文が Codex への指示の先頭に挿入される。継続セッション（`session_id` あり）の場合は既定で挿入されないが、`reinject_guideline=true` を指定すれば改めて挿入できる。

固定の指示文には次の区分の内容が含まれる。

| 区分 | 概要 |
|---|---|
| 出力ルール | 深刻度（Critical / Warning / Info / Suggestion）・ファイルパス・行番号の明記、具体的なコード例の提示 |
| 指摘の成立条件 | 文脈を踏まえて成立する問題のみを指摘、曖昧さ・矛盾・記述追加要求の立証内容、指摘が存在しない場合の報告 |
| ソースコード | 要件への準拠、正確性・ロジック、類似機能との整合性、アーキテクチャ、ワークフロー・連携影響、データライフサイクル、保守性、セキュリティ、パフォーマンス、テスト網羅性、オーバーエンジニアリング、根本原因への対処、将来の拡張を視野に入れる |
| ソースコード上のコメント | ドキュメンテーションコメントの使用、スコープ内の情報のみの記述、アノテーションの付与 |
| ドキュメント | 上位・別観点ドキュメントの修正漏れ、ドキュメント構成の最適化 |
| コメント / ドキュメント共通 | 記述のシンプルさ、履歴・経緯や削除・変更した機能への言及の混入禁止、他モジュールの責務への言及禁止、曖昧・口語的・非一般的な表現の禁止 |
| 全体構成 | 関連リソースの修正漏れ |
| AI エージェントによる不正行為 | 仕様・要件の簡略化や変形と、その後付けの正当化の検出 |

指示文の全文は `agents/codex-review-guidelines.txt` にあり、このファイルを編集すればレビュー指示に反映される。

また Codex には「コードの修正は行わず読み取りのみ」という制約が自動付加される。

## ログファイル

### 保存先

ログは git リポジトリルート（リポジトリ外ならカレントディレクトリ）配下の `.llm-ask/` に保存される。保存先は変更できない。
`.llm-ask/` フォルダを新規作成するときは `*` を対象とした `.gitignore` が自動生成される。
`.llm-ask/` フォルダが既に存在する場合は `.gitignore` の作成/編集は行われない。

### 構成

| セクション | 内容 |
|---|---|
| ヘッダー | 日時・モード（new / continuation）・ディレクトリ・セッション ID |
| メッセージ | 送信したレビュー指示原文 |
| Codex の回答 | Codex からのレビュー結果 |
| エラー情報 | エラー時のみ。exit code と stderr の内容 |

ログファイル名のパターン：`<YYYYMMDD_HHMMSS_mmm>_<プロジェクト名>_codex-review.md`

### session_id による継続レビュー

ログの `セッションID` 欄の ID を次回呼び出しの `session_id` に渡すと、同じ Codex スレッドで追加レビューを依頼できる。codex-ask の session_id も指定可能。

## Codex CLI 実行引数

Codex CLI は以下の固定引数で起動される。

| オプション | 値 | 説明 |
|---|---|---|
| サブコマンド | `exec` | 実行モード（非対話。承認は求められない） |
| `--skip-git-repo-check` | — | git リポジトリ外でも実行を許可 |
| `--sandbox` | `read-only` | サンドボックス: ファイル読み取りのみ許可 |
| `--json` | — | JSON 形式で出力 |
| `-m` / `-c model_reasoning_effort=` | — | `CODEX_REVIEW_DEFAULT_MODEL` を指定した場合のみ付与 |

`session_id` を指定した場合は `exec` の後に `resume <session_id>` が付加される。

## モデルの指定

使用するモデルと reasoning effort は、呼び出し時の `model=` / `effort=` 指定と環境変数 `CODEX_REVIEW_DEFAULT_MODEL` の 2 通りで指定できる。

| 優先順 | 指定方法 |
|---|---|
| 1 | 呼び出しプロンプトの `model=` / `effort=`（agent が `--model` / `--effort` として渡す） |
| 2 | 環境変数 `CODEX_REVIEW_DEFAULT_MODEL` |
| 3 | 未指定（既定モデル） |

`model` と `effort` は独立に上書きされる。`model` だけを明示指定した場合、effort は環境変数由来の値（無ければ未指定）のままになる。

agent は**ユーザーが明示的にモデルや effort を指定した場合のみ** `--model` / `--effort` を付与する。指定が無い場合は付与せず、環境変数または既定モデルが使われる（従来と同じ挙動）。

環境変数 `CODEX_REVIEW_DEFAULT_MODEL` の書式は次のとおり。

| 書式 | 例 | 動作 |
|---|---|---|
| `<model>` | `gpt-5` | モデルのみ指定する |
| `<model>,<effort>` | `gpt-5,high` | モデルと reasoning effort を指定する |
| 未設定 / 空文字列 | — | codex CLI 既定のモデルを使用する |

呼び出し時の指定・環境変数のいずれで指定した値も、`codex` の `-m`（model）と `-c model_reasoning_effort=`（effort）にそのまま渡される。プラグイン側で値の妥当性は検証しないため、不正な値を指定した場合は codex 側がエラーを返し、その内容がログの「エラー情報」に記録される。

## エラー処理

| 状況 | 動作 |
|---|---|
| `review_instruction` が不足 | 引数不正メッセージを出力して終了 |
| `codex` 未インストール | `'codex' コマンドが見つかりません` を出力して終了 |
| Python 3.10+ が見つからない | `python-wrapper.sh` が固定メッセージで終了 |
| Codex の実行エラー | エラー内容をログに含めてパスを返す（exit code 1） |
